# MITM Request Sanitizers

**Status (2026-11-14):** Implemented (`src/docker/request-sanitizers/`): provider-hosted tools are stripped unconditionally and each removal is logged; a request the sanitizers cannot parse is refused.

## Context

The MITM proxy terminates TLS for every LLM provider the agent may reach, filters method+path against an endpoint allowlist and swaps the sentinel key for the real credential. Endpoint filtering alone does not stop **provider-side egress**: a completion request can ask the provider itself to reach the network. Server-side tools (e.g. `web_search_20250305`) execute on the provider's infrastructure and bypass both network isolation and the MCP policy engine — the agent fetched live news stories with zero MCP tool calls recorded. The same holds for the Anthropic MCP connector (`mcp_servers`), code-execution containers and Agent Skills (`container`), and content blocks whose `source` is a URL, which the provider downloads while answering. The OpenAI Responses and Chat Completions APIs have the same classes: hosted `web_search`, remote `mcp` servers (`server_url`), `file_search`, `code_interpreter`, `image_generation`, and `input_image`/`input_file`/`image_url` parts that name an http(s) URL; Z.AI's GLM chat API adds `web_search` and `retrieval` tools. Codex even declares a live `web_search` tool on every request by default. Gemini has the same features as Tool keys (`googleSearch`, `urlContext`, `codeExecution`, ...) and URI-referencing parts (`fileData`), and OpenRouter adds its own on top of every protocol it serves (the `web` plugin, `:online` model variants, web-search models). A prompt-injected agent with a shell can send such a request itself, through `HTTPS_PROXY`, with the sentinel (the proxy swaps in the real key; since the provider credential gate in `src/docker/provider-credentials.ts`, any other credential gets a local 401), and exfiltrate workspace data or pull in unmediated web content without an escalation or an audit record.

The first fix stripped typed `tools[]` entries on `api.anthropic.com/v1/messages` only, ignored the other fields above and `count_tokens`, and forwarded a body it could not parse **as-is**. This design replaces it with a per-protocol allowlist sanitizer framework that fails closed.

**Decision:** provider-hosted tools are stripped unconditionally (no per-profile opt-in), and each removal is logged.

## Framework (`src/docker/request-sanitizers/`)

- **`RequestSanitizer`** (`core.ts`): one per wire protocol. `sanitizeBody(body)` returns the body to forward plus one label per removed or neutralized item, returning the input object itself when nothing changed; it never mutates its input. `sanitizeHeaders(headers)` edits the forwarded headers in place. A request that cannot be made safe throws `RequestRejectedError` (code `REQUEST_REJECTED`, status 400) instead of being passed through.
- **Registry** (`index.ts`): sanitizers are registered under their completion protocol id: `anthropic-messages`, `google-generate-content`, `openai-responses` and `openai-chat-completions`, which covers every built-in completion protocol. `sanitizedEndpointsFor(protocol, paths)` builds bindings and returns `[]` while a protocol has no sanitizer.
- **Gateway sanitizers**: a gateway that adds egress features of its own to the protocols it serves declares a gateway-level sanitizer in its definition (`GatewayDefinition.gatewaySanitizer`, today only `'openrouter'`). `makeGatewayProvider` builds it for the session's profile and passes it to `sanitizedEndpointsFor(protocol, paths, gatewaySanitizer)`, which chains it in front of the protocol's sanitizer (`chainSanitizers`: the gateway layer runs first, the protocol sanitizer runs on its output, both sets of labels are reported, and the log names both, e.g. `openrouter+anthropic-messages`). The gateway layer is bound even while the protocol has no sanitizer of its own; the protocol's rules join it on registration. OpenAI's own routes bind a provider layer the same way: `openaiPlatformSanitizer` (`openai.ts`) runs in front of the OpenAI protocol sanitizers on api.openai.com's two completion routes and on the ChatGPT Codex backend, and refuses OpenAI's web-search models (see [the OpenAI section](#openai-responses-and-chat-completions-sanitizers-openaits)). Both layers match the model against one shared list of name patterns (`web-search-models.ts`).
- **Binding** (`ProviderConfig.sanitizedEndpoints`): explicit `{ method: 'POST', path, sanitizer }` entries, matched like `allowedEndpoints` (query string stripped, `*` matches unreserved characters within one segment, never only dots). `resolveRequestSanitizer(config, method, path)` finds the binding. Built-in providers declare a binding for every completion endpoint, plus same-format siblings such as `count_tokens`; a declaration stays inert (`[]`) until its protocol registers a sanitizer, so a protocol added later picks its sanitizer up on registration. Gateway providers (`makeGatewayProvider`) bind **every POST route** of the protocol, and the binding is independent of the caller-supplied rewriter. A test asserts that every built-in completion endpoint whose protocol has a registered sanitizer is bound to it (behind the gateway layer where there is one), so new sanitizers extend coverage automatically.
- **Content decoding** (`content-encoding.ts`): a buffered body with `Content-Encoding` `gzip` (or `x-gzip`), `deflate` (zlib format), `br` or `zstd` is decoded before the pipeline, asynchronously and bounded: decoding stops as soon as the output passes the provider's buffering limit (`ProviderConfig.maxRequestBodyBytes`; 413), so a decompression bomb never allocates more, and the zstd decoder accepts windows up to 2^24 bytes only, so a crafted frame cannot claim a 128 MiB buffer. The proxy also charges every decoded chunk to the bundle's buffered-body budget as the decoder produces it (`decodeRequestBody`'s `reserve` hook; 503 when the budget is spent) and decodes one body at a time per bundle, so concurrent bombs that each stay under the per-request limit cannot together hold more than the budget, even while they decode. Corrupt or truncated data is a 400; an unknown coding or several stacked codings (repeated headers count) a 415, decided before the body is buffered. The forwarded request carries the decoded canonical JSON and no `Content-Encoding`. Codex enables zstd request compression by default (`enable_request_compression`, aimed at the ChatGPT backend), so refusing compressed bodies could break every Codex turn on that route.
- **Pipeline** (`processRequestBody`, or `parseJsonObjectBody` + `processParsedRequestBody` when the caller needs the parsed object too): strict UTF-8 decode → `JSON.parse` → the body must be a JSON object → every own `__proto__` key is deleted, at any depth → the provider's compatibility `requestRewriter` (model mapping, schedule-tool strips, gateway fields) → the sanitizer, on the rewriter's output, so it sees what leaves the proxy → `JSON.stringify`. With a sanitizer, the proxy always forwards the **canonical serialization** of the sanitized body (it reuses the raw bytes only when they are identical, which is the case for Claude Code's own `JSON.stringify` output). The upstream therefore parses exactly what was inspected: duplicate keys, invalid UTF-8 or other parser differentials cannot hide a hosted tool. For the same reason `sanitizeRequestHeaders` declares the forwarded body as plain `Content-Type: application/json`, whatever the agent sent: an upstream that honors an agent-chosen charset or media type would decode different fields out of the same bytes (under `charset=utf-7`, `+ACI-` inside a JSON string is a quote that ends it early, so `"metadata":{"user_id":"+ACIAfQ-,+ACI-mcp+AF8-servers..."}` becomes a top-level `mcp_servers`; under a form-encoded type, `&mcp_servers[0][url]=...` inside a string becomes a field). Express's `body-parser` honors `charset=utf-7`, for example. `__proto__` keys are dropped because `JSON.parse` keeps them as plain data the sanitizer never looks into, while a JavaScript gateway that copies the body with assignment semantics (`Object.assign`, schema passthrough) would turn `{"__proto__":{"tools":[…]}}` into a real `tools` field. Rewriter-only routes keep the raw bytes unless the body changed, but also reject a body that does not parse.
- **Credentials are checked first, sanitization applies to everything after**: the provider credential gate (`src/docker/provider-credentials.ts`) answers a request that carries any credential other than the session sentinel, or none on an endpoint that is not declared unauthenticated, with a local 401 before any buffering. Every request that passes the gate is sanitized on a bound endpoint, whatever it presented. No completion endpoint is declared unauthenticated.

### Request flow in `mitm-proxy.ts`

1. Endpoint allowlist (403), then the credential gate: the agent's hop-by-hop request headers and every credential carrier (key headers, cookies, credential query parameters) are stripped, the sentinel becomes the real key in the provider's configured location, and any other credential, or none outside the provider's `unauthenticatedEndpoints`, is a local 401.
2. `needsRewrite = shouldRewriteBody(...)`, `sanitizer = resolveRequestSanitizer(...)`; the body is buffered when either applies (or for a small 401-retry body).
3. On such a route, a `Content-Encoding` other than identity, gzip, deflate, br or zstd gets **415**. The body is read by `readRequestBody` (`mitm-resource-limits.ts`) within the provider's documented request limit, `ProviderConfig.maxRequestBodyBytes`: 32 MiB by default (Anthropic's 32 MB), 50 MiB for `api.openai.com` and the Codex backend on `chatgpt.com` (OpenAI's 50 MB per-request payload). A larger raw body gets **413** (`request_too_large`, naming the limit) with `Connection: close`: a declared `Content-Length` over the limit is refused before anything is buffered, a chunked body as soon as it passes the limit. The response is written at once, and the rest of the upload is read and discarded (up to 64 MiB or 30 s) before the connection closes, so a fetch client that reads only after it finishes writing still receives the 413 instead of a reset. Buffered bytes are also charged to the bundle's budget (503 when it is spent; see `docs/designs/tls-terminating-api-proxy.md`). The trajectory capture records the raw (possibly compressed) bytes with their encoding.
4. `decodeRequestBody` for a compressed body (**400** for corrupt data, **413** when it decodes past the same limit, **503** when the bundle's buffered-body budget cannot hold the decoded bytes), then `parseJsonObjectBody` once: the parsed object feeds both the token-stream tool-result extraction and `processParsedRequestBody`, so a large body is parsed once, not twice; a `RequestRejectedError` becomes a local answer with its status and a JSON error body (`{"type":"error","error":{"type":"invalid_request_error","message":"IronCurtain proxy refused this request: …"}}`, readable by both the Anthropic and OpenAI SDKs). Claude Code does not retry a 400. Any other exception becomes a 500. In every case nothing is sent upstream.
5. A decoded body loses its `Content-Encoding` header. `sanitizeRequestHeaders(sanitizer, modifiedHeaders)`: sets `Content-Type: application/json` (replacing any agent-declared media type or charset), then applies `sanitizer.sanitizeHeaders`; the 401 retry reuses the sanitized headers and body. Metrics observe the decoded request.
6. Forward.

## Anthropic Messages sanitizer (`anthropic.ts`)

Bound to `api.anthropic.com` `/v1/messages` and `/v1/messages/count_tokens` (API key and OAuth providers), Z.AI `/api/anthropic/v1/messages` and its `count_tokens`, and OpenRouter `/api/v1/messages` and its `count_tokens` (behind the OpenRouter layer).

| Item                              | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tools[]`                         | Keep only client-executed tools: entries with no `type` or `type: "custom"`. Every typed entry (`web_search_*`, `web_fetch_*`, `code_execution_*`, `mcp_toolset`, `computer_*`, `bash_*`, `text_editor_*`, and types that do not exist yet) and every non-object entry is dropped.                                                                                                                                                                                                                        |
| `mcp_servers`, `container`        | Dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Content blocks with `source`      | Kept only when `source` is an object whose `type` is inline data (`base64`, `text`, `content`); anything else (`url`, `file`, a missing or unknown type, or a bare string, array or `null` source) is replaced by a text placeholder that keeps the block's `cache_control`. The one exception is the string `source` of a `search_result` block, a citation label that is never fetched. Applies to message content, nested `tool_result` content, `content` document sources and `system`, recursively. |
| Replayed provider tool activity   | `server_tool_use`, `mcp_tool_use`, every `*_tool_result` other than the client `tool_result`, and `container_upload` are dropped from history. A block list emptied this way gets the placeholder so the message stays valid.                                                                                                                                                                                                                                                                             |
| `anthropic-beta` header           | Values starting with `mcp-client-`, `web-fetch-`, `web-search-`, `code-execution-`, `computer-use-`, `skills-` or `files-api-` (case-insensitive) are removed; the header is deleted when nothing remains. This is a denylist on purpose: Claude Code is not pinned and adds betas often, so an allowlist would break sessions; the body rules are the real control.                                                                                                                                      |
| `model`                           | Must be a string, else 400.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `tools`, `messages`, each message | Must be an array, an array and an object respectively when present, else 400.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Content block lists               | Every entry must be an object, else 400: a nested array, string or `null` is nothing the sanitizer can inspect, and a lenient upstream that flattened or coerced it would receive unchecked blocks.                                                                                                                                                                                                                                                                                                       |
| Nesting                           | Content nested more than 8 levels deep is refused (real requests nest at most three).                                                                                                                                                                                                                                                                                                                                                                                                                     |

Everything else passes through untouched, so Claude Code's ordinary requests (custom and deferred tools, base64 images and PDFs, thinking blocks, `tool_reference` results, `cache_control`, `context_management`, `metadata`) are forwarded byte-for-byte with the same betas. `anthropicRequestRewriter` keeps only the Claude Code compatibility rewrite: stripping the schedule-skill tools and their history references for one-shot batch and workflow agents.

Gateway notes:

- Every gateway completion route rejects a request without a string `model` (`makeGatewayRequestRewriter`); on OpenRouter, whose model selection is proxy-owned, forwarding it unmapped would let the provider pick a model the profile never approved.
- `GatewayDefinition.filterMessagesTools` now only controls the schedule-skill compatibility rewrite on the messages route; hosted-tool removal applies to every messages route.
- On OpenRouter the sanitizer runs after model mapping, so it sees the final model.

## OpenAI Responses and Chat Completions sanitizers (`openai.ts`)

`openai-responses` is bound to api.openai.com `/v1/responses`, the ChatGPT Codex backend `chatgpt.com/backend-api/codex/responses`, Z.AI `/api/v1/responses` and OpenRouter `/api/v1/responses`. `openai-chat-completions` is bound to api.openai.com `/v1/chat/completions`, Z.AI `/api/paas/v4/chat/completions` and `/api/coding/paas/v4/chat/completions`, and OpenRouter `/api/v1/chat/completions`. On OpenRouter both run behind the OpenRouter layer (`openrouter+openai-responses`, `openrouter+openai-chat-completions`). Neither protocol has a request header that enables hosted features, so only the body is rewritten.

On OpenAI's own routes they run behind the `openai-platform` layer: both on api.openai.com (`openai-platform+openai-responses`, `openai-platform+openai-chat-completions`), and `openai-responses` on the ChatGPT Codex backend (`openai-platform+openai-responses`). Every Codex session reaches OpenAI by that backend, and a process in the container can name any model on it; whether the backend would serve a search model is unverified, so the layer refuses one there too. OpenAI's search models search the web on every request just by being named: `gpt-4o-search-preview`, `gpt-4o-mini-search-preview` and `gpt-5-search-api` (and their dated snapshots) on Chat Completions, and the deep-research models `o3-deep-research` and `o4-mini-deep-research` on Responses. No request field turns that off, so the layer answers a request naming one with a 400 (`model "gpt-4o-search-preview" searches the web on every request, which the proxy does not forward; use a model without built-in web search`), comparing the model trimmed and case-folded against the shared patterns (a name ending in `-search` or containing `-search-`, `deep-research`, and the OpenRouter-only `perplexity/` and `-online` slugs). There is no exception for a user-chosen model: provider-hosted web search is stripped unconditionally. The protocol sanitizers themselves stay model-agnostic, because Z.AI and OpenRouter reuse them for model namespaces of their own; on OpenRouter the gateway layer decides, and keeps forwarding a search model the profile names.

The allowlists come from requests recorded from the pinned Codex CLI (see [Codex](#codex)), not from documentation, so they keep exactly what the client executes itself.

| Item (Responses)                         | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tools[]`                                | Keep `function`, `custom` (Codex's `apply_patch`), `local_shell`, `namespace` and `tool_search` with `execution: "client"`. A `namespace` (Codex groups each MCP server's tools and its multi-agent tools in one) keeps only `function`/`custom` members and is dropped when none remain. Everything else is dropped: `web_search*`, `file_search`, `code_interpreter`, `image_generation`, `mcp`, `computer_use*`, a hosted `shell`, a server-side `tool_search`, unknown types and non-objects.                                                                                                                                                                                                                                                                                       |
| `tool_choice`                            | Kept when it is `none`/`auto`/`required` or names a `function` or `custom` tool; an `allowed_tools` choice keeps only such entries. Any other choice (`web_search_preview`, `mcp`, `file_search`, …) is removed, so the default applies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `input[]` items                          | Kept: `message` (also the typeless `{role, content}` form), `reasoning`, `function_call(_output)`, `custom_tool_call(_output)`, `local_shell_call(_output)`, `compaction`, and `tool_search_call`/`tool_search_output` with `execution: "client"`. Dropped: replayed provider-side items (`web_search_call`, `mcp_call`, `mcp_list_tools`, `mcp_approval_request`/`_response`, `file_search_call`, `code_interpreter_call`, `image_generation_call`, `computer_call*`), `item_reference` and unknown types.                                                                                                                                                                                                                                                                             |
| `tool_search_output.tools`               | The same allowlist as `tools[]`: these definitions become callable, so an injected `mcp` or `web_search` entry is dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Content parts (messages and tool output) | Text parts pass. `input_image`, `input_file` and `input_audio` are kept only when their data is inline: every `*url`/`*uri` field a `data:` URL, `file_data`/`data` a data URL or base64, no stored reference (a field ending in `id`, such as `file_id`) and no other field naming a URL (`src`, `href`, …); field names are compared ignoring case, `_` and `-`, so `fileId` counts. Otherwise, and for any unknown part type, the part is replaced by an `input_text` placeholder (`output_text` in assistant messages). This also applies to a part list in `local_shell_call_output` (typed as a string by the API). A reasoning item's `summary`/`content` lists keep only `summary_text`/`reasoning_text` parts. Labels name the field (`input_image:image_url`), never the URL. |
| `prompt`, `web_search_options`           | Dropped. A stored prompt's variables can carry URL-sourced images and files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Malformed requests                       | 400: a non-string `model`; non-string `instructions`; `tools`, `input`, message content or tool output of the wrong JSON kind; a non-object item or content part.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Field spellings                          | 400 when an object the sanitizer inspects (the body, a tool or namespace member, an input item, a content part) spells a field it reads or removes in another form: `Tools`, `TYPE`, `toolChoice`, `web-search-options`, or `tool\u017f` (U+017F folds to `s`). The sanitizer reads only the exact name, but a JSON decoder that matches names case-insensitively (Go's `encoding/json` does, and the last spelling wins) would read `{"type":"function","TYPE":"web_search"}` as a web search tool. No client sends such spellings; fields the sanitizer does not inspect (schema properties, metadata) are left alone.                                                                                                                                                                |

Chat Completions follows the same rules in its own shapes: `tools[]` keeps `function` and `custom` (Z.AI GLM's `web_search`, `retrieval` and `mcp` tools are dropped, as is anything untyped), `tool_choice` likewise (`allowed_tools.tools` for the allowlist form), `web_search_options` is dropped, and message content keeps `text`/`refusal` plus inline `image_url`, `input_audio` and `file` parts; an http(s) `image_url`, a `file_id`, and unknown parts such as GLM's `video_url`/`file_url` become a `text` placeholder. `messages` must be an array of objects, and variant spellings of `messages`, `tools`, `tool_choice`, `web_search_options`, `model`, a tool's or part's `type` or a message's `content` are refused.

Everything else passes through untouched, so Codex's and Goose's ordinary requests are forwarded unchanged, byte-for-byte when they are already canonical JSON (Codex's serde output is).

## Codex

- **Recorded wire format.** `test/docker/fixtures/codex-responses-request.json` (built-in OpenAI provider, MCP tools deferred behind a client `tool_search`) and `codex-zai-responses-request.json` (the generated Z.AI profile, MCP tools in a `namespace`) are the last requests of a Codex 0.157.1 turn that ran a shell command, `apply_patch`, `view_image` (an inline `data:` image), `tool_search` and an MCP call. They were recorded offline: Codex ran in a network namespace with only loopback, against a local Responses stand-in. Host paths are replaced and long prompt texts elided; every item, tool and field keeps its recorded shape. Tests assert the sanitizer removes only the default `web_search` tool from them, and nothing at all once web search is disabled.
- **Pinned client.** `docker/Dockerfile.codex` installs `@openai/codex@${CODEX_VERSION}` (`ARG CODEX_VERSION=0.157.1`, recorded as `CODEX_CLI_VERSION` in `src/docker/agent-cli-version.ts`), and a test ties the pin to the recordings. Re-record before bumping it: a new client tool or item type would otherwise be dropped in flight. An `agentCliVersions.codex` override builds another client, which this applies to as well; a version outside the qualified range is logged as a warning at session start.
- **Web search off at the source.** The generated `config.toml` sets `web_search = "disabled"`. Codex otherwise declares `{"type":"web_search","external_web_access":true}` on every request under `--sandbox danger-full-access`. The agent can edit its own config, so the sanitizer stays the control; the setting keeps Codex from offering the model a tool that would only be removed.
- **POST + SSE only.** The proxy refuses WebSocket upgrades on provider hosts and never bridges them, so every request reaches the sanitizer as an HTTP body. Codex's built-in ChatGPT provider prefers `wss://chatgpt.com/backend-api/codex/responses` and fell back to POST only after about 7 s of refused handshakes per turn. The generated config therefore binds every route to a provider with `supports_websockets = false`. Codex cannot redefine its built-in `openai` provider, so the native route gets `[model_providers.ironcurtain-chatgpt]`: the built-in definition (name `OpenAI`, Responses, ChatGPT login, the `version` header of the pinned client, no `base_url`) with WebSockets off. Offline, against a local stand-in, Codex 0.157.1 sent the same request headers and body through this binding as through the built-in provider (apart from per-session ids; zstd-compressed in both cases), and no handshake first. The opt-in `test/docker/codex-websocket-live.integration.test.ts` repeats such a turn through the proxy with the installed client. The chatgpt.com allowlist has no `GET /backend-api/codex/responses`: the GETs earlier runs showed on that path were the handshakes.
- **Compression.** Codex 0.157.1 enables `enable_request_compression` by default and compresses with zstd (`Content-Encoding: zstd`) when it is logged in with ChatGPT: offline, against the stand-in above, its ChatGPT-route completions were zstd bodies through the built-in provider and through the generated binding alike. The API-key and Z.AI requests recorded here were not compressed. The proxy decodes such bodies (see Content decoding), so either way Codex keeps working.
- **Workspace routing discovery.** In ChatGPT mode, Codex 0.157.1 first calls `GET /backend-api/wham/accounts/check` and fails the turn ("workspace routing discovery failed") when it does not succeed, so the chatgpt.com allowlist includes that read-only GET; the rest of the list was enumerated from Codex 0.139.0. The call was observed offline only; a live run has not confirmed it yet.

## Gemini generateContent sanitizer (`gemini.ts`)

Bound to `generativelanguage.googleapis.com` `/v1beta/models/*:generateContent` and `/v1beta/models/*:streamGenerateContent` (`googleProvider`, used by Goose's Google provider).

Google parses request JSON with the proto3 mapping, which accepts both the lowerCamelCase and the snake_case name of every field, so every rule covers both spellings (`functionDeclarations`/`function_declarations`, `urlContext`/`url_context`, `fileData`/`file_data`, `systemInstruction`/`system_instruction`, ...).

| Item                                        | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tools[]`                                   | Inside each Tool object only `functionDeclarations` survives. One Tool can mix several keys, so each key is checked, not just whole entries: `googleSearch`, `googleSearchRetrieval`, `urlContext`, `codeExecution`, `computerUse`, `fileSearch`, `googleMaps` and keys that do not exist yet are dropped (`tool:<key>`). A Tool left without keys is dropped, as is a non-object entry.                                                                                                                                                                                                                                                                                                                                                         |
| Parts of `contents` and `systemInstruction` | Allowlisted by field: inline data (`text`, `inlineData`, `functionCall`, `functionResponse`) and metadata (`thought`, `thoughtSignature`, `videoMetadata`, `partMetadata`, `mediaResolution`). A part with any other field is replaced by `{"text": "<placeholder>"}`: `fileData` (Google fetches its `fileUri`, whether http(s), `gs://` or a Files API URI), replayed `executableCode` / `codeExecutionResult`, or an unknown field. The label names the URI scheme (`part:fileData:https`), never the URI.                                                                                                                                                                                                                                    |
| `functionResponse.parts`                    | A function response's own parts (multimodal function results) may carry `inlineData` only; any other part is dropped from the response (`functionResponse.part:<field>`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `cachedContent`                             | Dropped: a cached-content resource brings its own tools and contents, which never pass through the sanitizer. The agent cannot create one through the proxy (the endpoint is not allowlisted), so no session needs it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Shapes                                      | `tools`, `contents` and `parts` must be lists. A single object in their place is sanitized as a one-entry list and keeps its shape, in case a lenient parser reads it as one; any other value is a 400, as is a content, part or `functionResponse` that is not an object, or a `systemInstruction` that is not an object. `null` counts as absent.                                                                                                                                                                                                                                                                                                                                                                                              |
| Query string                                | Only `alt=sse` or `alt=json` (the response format; Goose streams with `alt=sse`) and `key` (an API key, a credential rather than content) are allowed; any other parameter or value is a 400. The sanitizer sees the forwarded path, from which the credential gate has already removed `key` (moved to `x-goog-api-key` when it carried the sentinel; any other value is a 401). Google's front end reads more than the body: query-string system parameters can override the request's Content-Type or headers (`$ct`, `$httpHeaders`), and other parameters are bound to request fields (`cachedContent=...`), so they would change what Google acts on without passing through the sanitizer. Names and values are compared percent-decoded. |

Everything else (`generationConfig`, `toolConfig`, `safetySettings`, ...) passes through untouched, so Goose's ordinary requests are forwarded byte-for-byte. Gemini names the model in the URL path, so the sanitizer requires no body `model`.

## OpenRouter gateway sanitizer (`openrouter.ts`)

OpenRouter adds egress features of its own to every wire protocol it serves: the web plugin, `:online` model variants, web-search models, fallback model lists and presets (saved settings, models included, applied by name). The OpenRouter definition declares `gatewaySanitizer: 'openrouter'`, so this layer runs on every OpenRouter POST route (`/api/v1/messages` and its `count_tokens`, `/api/v1/responses`, `/api/v1/chat/completions`), chained in front of the protocol's sanitizer (`openrouter+anthropic-messages` on the messages routes, `openrouter+openai-responses` on the responses route and `openrouter+openai-chat-completions` on the chat route). Like every sanitizer, it runs after the compatibility rewriter, so it sees the mapped model.

| Item                                                | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugins`, `web_search_options`, `models`, `preset` | Dropped. `plugins` carries the `web` search plugin (and file parsers); `web_search_options` tunes the native search of search models; `models` lists fallback models, which the profile's model map never sees and which could name any of the models below; `preset` applies a preset by name (see below). Names are compared ignoring case, `_` and `-`; a non-canonical spelling of `model` (`Model`, `MODEL`) is dropped too.                                                                                                                                                                                                                                          |
| `:online` variant                                   | Stripped from `model` (case- and space-insensitive; other variants such as `:nitro` stay), after mapping, so it goes whether the agent asked for it or a model-map target produced it (`model:online`). A model that still names `:online` in a form this cannot strip (e.g. `:online@preset/x`) is a 400.                                                                                                                                                                                                                                                                                                                                                                 |
| Web-search models                                   | Every `perplexity/` model, `*-search` and `*-search-*` slugs (OpenAI `*-search-preview`, `*-search-api`), `*deep-research*` and legacy `*-online` slugs (compared lowercased, without a leading `~` or `:variant`) are a 400 unless the provider profile names the model itself: as a model-map target, a per-agent model, the profile model or the gateway default. An agent cannot pick one on its own; a user who maps to one has chosen a model that searches the web on every request. A model chosen outside the profile (`agentModelId`, `gooseModel`, a workflow state's model) reaches OpenRouter as a requested model and is no approval: map it in the profile. |
| Presets                                             | A model that applies a preset (`@preset/<slug>`, alone or after a model slug as in `openai/gpt-4o@preset/<slug>`; any `@` counts, since no model slug contains one) is a 400 unless the provider profile names that exact model (compared lowercased and trimmed), on the same terms as web-search models. A preset is account configuration the proxy cannot see: its saved model list can name a web-search model or an `:online` variant, so an agent-chosen preset would get around both rules above.                                                                                                                                                                  |
| `model`                                             | Must be a string, else 400.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

Everything else passes through to the protocol sanitizer (hosted tools in `tools[]`, URL-sourced content, including OpenRouter's URL-valued `file.file_data` on the chat route, ...).

## Logging

Every removal is written to the session log (`logger.warn`), one line per request, with labels escaped and length-capped (agent-controlled values cannot forge log lines), duplicates counted and the list capped:

```
[mitm-proxy] POST api.anthropic.com/v1/messages - anthropic-messages sanitizer removed: anthropic-beta:mcp-client-2025-04-04, mcp_servers, tool:web_fetch_20250910, image:source:url
[mitm-proxy] POST chatgpt.com/backend-api/codex/responses - decoded zstd request body (9120 -> 45084 bytes)
[mitm-proxy] POST chatgpt.com/backend-api/codex/responses - openai-platform+openai-responses sanitizer removed: tool:web_search, tool:mcp, tool_choice:mcp, input:mcp_approval_response, input_image:image_url
[mitm-proxy] REJECTED POST api.anthropic.com/v1/messages - request body is not valid JSON
[mitm-proxy] POST generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent - google-generate-content sanitizer removed: cachedContent, tool:googleSearch, tool:urlContext, part:fileData:https
[mitm-proxy] POST openrouter.ai/api/v1/messages - openrouter+anthropic-messages sanitizer removed: plugins, model:online, tool:web_search_20250305
[mitm-proxy] REJECTED POST openrouter.ai/api/v1/chat/completions - model "perplexity/sonar" searches the web on every request; it is forwarded only when the provider profile maps to it
[mitm-proxy] REJECTED POST chatgpt.com/backend-api/codex/responses - unsupported Content-Encoding: compress
```

A replaced agent-declared `Content-Type` is logged as `content-type:<declared value>`; a missing one, `application/json` and `application/json; charset=utf-8` are normalized silently. Labels for a removed `source` name its type or JSON kind (`image:source:url`, `image:source:<string>`), labels for a removed Gemini `fileData` name the URI scheme (`part:fileData:gs`), and OpenAI part labels name the field (`input_image:image_url`, `file:file.file_id`), never the URL, which may carry exfiltrated data. A rejection message that quotes the agent's model escapes and truncates it like a label. Compatibility rewrites are logged at info level as `rewrote: <labels>`, decoded bodies as `decoded <coding> request body`. A route with a rewriter but no sanitizer logs pipeline removals (`key:__proto__`) as `request sanitizer removed: …`.

## Coverage

| Route                                                              | Sanitizer                                                                     |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Anthropic Messages: api.anthropic.com, Z.AI (incl. `count_tokens`) | `anthropic-messages`                                                          |
| OpenRouter `/api/v1/messages` (incl. `count_tokens`)               | `openrouter+anthropic-messages`                                               |
| OpenAI Responses / Chat Completions: Z.AI                          | `openai-responses`, `openai-chat-completions`                                 |
| api.openai.com `/v1/responses`, `/v1/chat/completions`             | `openai-platform+openai-responses`, `openai-platform+openai-chat-completions` |
| chatgpt.com `/backend-api/codex/responses` (Codex)                 | `openai-platform+openai-responses`                                            |
| OpenRouter `/api/v1/responses`, `/api/v1/chat/completions`         | `openrouter+openai-responses`, `openrouter+openai-chat-completions`           |
| Gemini `generateContent` / `streamGenerateContent`                 | `google-generate-content`                                                     |

Every built-in completion protocol has a sanitizer. A protocol added without one keeps its routes as before (rewriter-only routes now fail closed on unparseable bodies), apart from a gateway layer, which is bound from the start.

Known limits:

- The Anthropic sanitizer allowlists `tools` entries and content `source`s, but passes unknown top-level fields and unknown block types through so that additions in Claude Code releases other than the pinned one (an `agentCliVersions` override) keep working. api.anthropic.com validates its schema strictly and rejects foreign shapes, but an Anthropic-compatible gateway that also accepted, say, OpenAI-style `image_url` parts or case-insensitive field names (`MCP_SERVERS`) could act on content the sanitizer does not recognize. Whether Z.AI or OpenRouter do is unverified.
- The OpenAI sanitizers likewise pass unknown top-level fields; on OpenRouter the gateway layer in front of them drops `plugins`, `models` and `preset`. Unlike the Anthropic sanitizer, they refuse variant spellings of the fields they inspect (see Field spellings), which closes the case-insensitive-decoder differential for those fields. They do not restrict the model themselves; the layer in front of them does: on api.openai.com and the Codex backend (`chatgpt.com`) the `openai-platform` layer refuses OpenAI's search and deep-research models, and on OpenRouter the gateway layer refuses web-search models unless the profile names them. On Z.AI no layer checks the model. `previous_response_id` and `conversation` make the provider load stored context the proxy cannot see; that context cannot run a hosted tool, because tools are declared per request and sanitized there.
- The web-search model list (`web-search-models.ts`, shared by the OpenRouter and `openai-platform` layers) is a denylist of known name patterns: a new search model OpenRouter or OpenAI adds under another name passes until the list learns it. On OpenAI's own routes a fine-tuned model id whose own suffix matches a pattern (`ft:gpt-4o-mini:org:code-search-v2:id`) is refused too. A web-search model, or a preset, that the profile maps to is forwarded by design; a mapped preset is trusted with whatever its saved settings select. Router models such as `openrouter/auto` let OpenRouter pick the model; whether that pool can include a web-search model is unverified.
- The Gemini part allowlist names the fields documented today; a field Google adds later neutralizes the part (a placeholder, not a 400) until it is reviewed and allowlisted.

## Edge cases

| Scenario                                                                           | Behavior                                                                                                                                                   |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Malformed JSON, invalid UTF-8, empty body, non-object JSON                         | 400, nothing forwarded                                                                                                                                     |
| Non-string `model`; `tools`/`messages` of the wrong type; a non-object message     | 400                                                                                                                                                        |
| A non-object entry in a content block list (nested array, string, `null`)          | 400                                                                                                                                                        |
| Agent-declared `Content-Type` other than JSON (`charset=utf-7`, form, text)        | Replaced by `application/json` on sanitized routes and logged; the body is the canonical UTF-8 JSON                                                        |
| Content nested too deeply to walk or to re-serialize                               | 400                                                                                                                                                        |
| gzip, deflate, br or zstd body on a sanitized or rewritten route                   | Decoded, sanitized, forwarded as plain canonical JSON without `Content-Encoding`                                                                           |
| Corrupt or truncated compressed body; a zstd frame with a window over 16 MiB       | 400                                                                                                                                                        |
| Other or stacked `Content-Encoding` on a sanitized or rewritten route              | 415, before the body is buffered                                                                                                                           |
| Body over the provider limit (32 MiB default, 50 MiB OpenAI), raw or once decoded  | 413 with `Connection: close`, delivered after the upload is drained; no upstream request                                                                   |
| Nothing to remove                                                                  | Canonical serialization forwarded; identical to the raw bytes for `JSON.stringify` clients such as Claude Code                                             |
| Duplicate keys                                                                     | `JSON.parse` keeps the last value; only that canonical form is forwarded                                                                                   |
| A variant spelling of an inspected field on an OpenAI route (`Tools`, `TYPE`)      | 400 (a case-insensitive upstream decoder would read it); on OpenRouter the gateway layer drops variant spellings of `model` and `web_search_options` first |
| A `__proto__` key anywhere in the body                                             | Deleted (logged as `key:__proto__`) on every buffered route, with or without a sanitizer                                                                   |
| All tools are provider-defined                                                     | `tools` becomes `[]`, forwarded                                                                                                                            |
| Gemini Tool mixing `functionDeclarations` with a hosted key                        | Only `functionDeclarations` is kept in that Tool                                                                                                           |
| Gemini `fileData` part (any URI scheme)                                            | Replaced by a text placeholder part                                                                                                                        |
| OpenRouter `openai/gpt-4o:online`, mapped or not                                   | Forwarded as `openai/gpt-4o`                                                                                                                               |
| OpenRouter web-search model the agent picked (`perplexity/sonar`)                  | 400, nothing forwarded; forwarded only when the profile maps to it                                                                                         |
| OpenAI search/deep-research model on api.openai.com or Codex (`gpt-5-search-api`)  | 400, nothing forwarded, whoever chose it                                                                                                                   |
| OpenRouter preset the agent picked (`@preset/x`, `model@preset/x`); `preset` field | 400 unless the profile maps to that model; the `preset` field is dropped                                                                                   |
| Gemini query parameter other than `alt=sse`/`alt=json` or `key` (`$ct=...`)        | 400, nothing forwarded                                                                                                                                     |
| Request carrying a credential other than the sentinel (header, cookie or query)    | 401 from the credential gate, nothing forwarded                                                                                                            |
| Request without any credential                                                     | 401 from the credential gate, nothing forwarded (only housekeeping endpoints are declared unauthenticated; none is a sanitized route)                      |
| Route with neither sanitizer nor rewriter                                          | Zero-copy `pipe()` path (no buffering)                                                                                                                     |
| Integers beyond 2^53                                                               | Lose precision in the canonical serialization (JavaScript numbers); LLM API requests do not carry them in practice                                         |

With Codex, the generated config disables web search; a Codex request carrying `{"type":"web_search"}` (e.g. from a nested `codex exec --search`) logs `openai-platform+openai-responses sanitizer removed: tool:web_search`. With Goose on Gemini the log shows `google-generate-content sanitizer removed: tool:googleSearch`; on an OpenRouter profile, a request for `openai/gpt-4o:online` is forwarded as `openai/gpt-4o` and logged as `model:online`.

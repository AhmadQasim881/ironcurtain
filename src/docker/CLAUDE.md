# Docker Agent Mode (`src/docker/`)

An alternative session type runs external coding agents (Claude Code, Goose, Codex) inside containers whose external traffic passes through host policy proxies. Ordinary Linux Docker and Apple `container` sessions use `--network none` with UDS-mounted proxies. macOS Docker Desktop uses an internal network and a TCP transport sidecar. Admitted WSL2/Desktop amd64 nested-Docker sessions use the shared daemon-sidecar lifecycle; online agents and daemons start on isolated relay networks, and fixed relays reach exact host policy sockets. Agent users retain sudo by default (`agentSudo`, see `agent-privileges.ts`) without receiving host runtime sockets or network administration capabilities.

Host code that touches agent-writable paths (the workspace, conversation-state directories, dependency layers) uses the no-follow primitives in `../hardened-fs.ts` (`readUntrustedRegularFile`, `writeFileNoFollowAtomic`, `appendRegularFileNoFollow`); agent-influenced text shown on a terminal goes through `../terminal/display-sanitize.ts`.

## Core session files

- Workflow staged resources use the orchestrator's explicit `workflowRunDir`, including external standalone runs. Validate scripts through `../workflow/staged-directories.ts` before reading dependency manifests and again before creating the mount plan; never infer the trusted run root from a checkpoint-selected scripts path.
- `docker-agent-session.ts` - Session implementation. Manages container lifecycle, starts proxies, handles escalations. Construction takes an `ownsInfra: boolean` flag that gates teardown: standalone sessions own the bundle and destroy it on `close()`; workflow shared-container sessions borrow a caller-supplied bundle (`ownsInfra: false`) and leave it alive. Each turn opens a budget-gate turn, runs under the in-container wall clock (`turn-timeout.ts`), and is preceded by the between-turn budget admission (`../session/budget-admission.ts`); a spent budget or a timed-out turn ends with `BudgetExhaustedError`. Conversation continuity uses the probes in `conversation-state.ts` and the agent thread id an adapter reports. Startup readiness permits at most 180 seconds by default for slow home ownership remapping.
- `docker-infrastructure.ts` - Shared `DockerInfrastructure` bundle used by batch, PTY, and workflow sessions. `buildAgentContainerConfig` assembles their common environment, UID remapping, resource limits, mounts, and nested-Docker wiring; the user, capabilities, no-new-privileges and exec user come from `agent-privileges.ts`. The bundle holds proxies, orientation, CA, fake keys, image resolution and the bundle's budget gate (`budgetGate`). Storage-check and provisioning errors quote bounded `toDisplayText` output; never interpolate raw container diagnostics into terminal errors. Workflow runs create one bundle per container scope and lend it to state sessions (`maxLanes` sizes its circuit breaker; `workflowCommit` is threaded through `createCodeModeProxy` to the sandbox; a read-only workspace is recorded as `readOnlyWorkspace` and refused together with nested Docker). On Linux Docker it refuses a root host identity before any image build (`assertLinuxDockerHostIdentity`) and warns when container root is host root (`ironcurtain doctor` reports both: 'Host identity', 'Docker user namespace'). Images are built under `<repo>:build-<hash16>` (`image-identity.ts`); `selectResumableSnapshot` resumes a workflow snapshot only for the same agent build hash and reports why not otherwise (`snapshotRefusal`); snapshot resume supplies `baseImageOverride` while retaining the ordinary agent build identity for dependency-cache bookkeeping.
  - **Active-profile config-stamping (OpenRouter, F1).** `prepareDockerInfrastructure` resolves the session's provider profile via `resolveActiveProfile(config.userConfig.modelProviders, providerProfileName)` and **stamps `config.activeProviderProfile`** as its **first step — before auth detection** (Claude Code's `detectCredential(config)` reads the stamped profile to return an API-key auth method for an OpenRouter-only user). An unknown `providerProfileName` throws (listing available profiles) before container launch. Everything downstream (`resolveRealKey`, adapters' `getProviders`/`buildEnv`) reads the per-session stamped `config.activeProviderProfile` — **binding the profile at adapter-factory/registry time is forbidden** (the registry caches adapter instances across sessions, so a factory-captured profile would leak between concurrent sessions). The same rule covers every session-specific value: the agent model (`config.agentModelId`, `buildCommand`'s `agentModelId`) and Goose's provider and model (`config.userConfig`).
- `docker-manager.ts` - Docker CLI wrapper implementing `ContainerRuntime`. `getImageLabel()` reads labels for staleness detection. `buildImage()` accepts optional labels and `noCache`. `streamContainerLogs()` streams a container's full log into a sink. Workflow snapshot resume also uses `commit()`, `removeImage()`, `listImages()`, and `inspectImage()`; flattened snapshot commits use `docker export`/`docker import` so superseded snapshot digests can be removed without leaving the prior digest inspectable as an image parent.
- `container-runtime.ts` - Runtime selection seam: `createContainerRuntime(kind, endpoint?, options)` returns the Docker or Apple implementation (Docker only: `defaultExecUser`, the numeric agent UID of sudo-off bundles; see `agent-privileges.ts`). Admitted Docker sessions capture one canonical local endpoint and preserve it through image preparation, create, relay, watchdog, and recovery operations; v2 and v3 Docker leases store that endpoint. Docker-specific host services call `createDockerManager()` directly.
- `apple-container-manager.ts` - Apple `container` CLI wrapper implementing `ContainerRuntime` (macOS 26+ on Apple silicon, VM per container, `container` >= 1.2.1). `checkAppleContainerAvailable()` is the availability probe. All mounts emit via `-v src:tgt[:ro]` (dirs, single files, and per-file UDS vsock relays uniformly); interactive sessions use runtime-native `container exec -it` under a host node-pty whose output is filtered (`pty-host-terminal.ts`), because the 1.1.0 published-socket relay can accept and close without reaching the guest listener. Docker-only mechanisms (`extraHosts`, `restartPolicy`, `connectNetwork`) throw instead of degrading silently. Host reconciliation uses normalized `container list --all --format json` inventory with exact IDs, state, creation time, and labels; VMs carry owner labels and are reconciled. The only module allowed to spawn the `container` binary.
- `network-topology.ts` - Proxy-transport topology (`uds` | `tcp-sidecar` | `tcp-hostonly`). apple-container resolves to `uds` (per-file `-v` socket relays + `--network none`); Docker resolves to `uds` on Linux and `tcp-sidecar` on macOS. `tcp-hostonly` (host-only vmnet, 16-subnet pool, `0.0.0.0` proxies guarded by `makeSourceAddressGuard`, `checkHostOnlyConnectivity`) is retained but not currently selected — it was the pre-1.1.0 apple-container path. Backend selection: `containerRuntime` config field (`auto` default — prefers apple-container when its probe passes; resolution memoized in `container-runtime.ts`), overridable via `IRONCURTAIN_CONTAINER_RUNTIME`. `buildUdsSocketMounts` in `docker-infrastructure.ts` is the runtime-keyed `uds` mount helper (dir mount on Docker, per-file on apple-container) shared by batch and PTY modes. In `tcp-sidecar` the MITM binds `127.0.0.1`.
- `transport-sidecar-image.ts` - The macOS `tcp-sidecar` socat image, built locally from `docker/transport-sidecar/Dockerfile` (never pulled by name) and created from its build-hash-labelled image ID; `ensureTransportSidecarImage` and `hardenTransportSidecarCreate` (read-only, unprivileged, all capabilities dropped) are its only entry points. Ordinary Desktop TCP bundles require per-bundle MCP/proxy admission and a CA/server-name-verified TLS host hop; `tcp-transport-sidecar.ts` binds listeners to the internal address/subnet. Desktop PTYs use native Docker exec without a published port. See `docs/designs/docker-desktop-tcp-admission.md`.
- `agent-privileges.ts` - Single source of the agent container user, capabilities, no-new-privileges, probe and exec user, for batch, PTY and dependency-provisioning containers. `agentSudo` (default on) keeps passwordless sudo; with it off the container runs unprivileged (Linux needs host UID 1000).
- `host-mount-privilege-scan.ts` - On Linux daemons where container root is host root, sweeps the agent's read-write bind mounts after each turn, at teardown and after dependency provisioning: strips setuid/setgid bits from files the host user owns and reports the ones it cannot change and every root-owned entry. It never follows a symlink and never moves or deletes anything. Startup/provisioning and recovery findings must reach the diagnostic callback or safe stderr fallback. Completed job notices and a separate bounded browser warning list preserve cleanup warnings after the live session ends; this remains advisory reporting.
- `turn-timeout.ts` / `exec-deadline.ts` - The per-turn wall clock (`maxSessionSeconds`) enforced inside the container (coreutils `timeout` plus an `IRONCURTAIN_TURN_ID` marker sweep; the host deadline is a backstop), and the exec deadline classification shared by the Docker and Apple managers.
- `image-identity.ts` / `agent-cli-version.ts` - Build identity of the base and agent images (`:latest` is only a moving alias; agent Dockerfiles take `ARG IRONCURTAIN_BASE_IMAGE`), and the pinned agent CLI versions (`cliVersion` per adapter; config.json `agentCliVersions` can override the npm-installed Claude Code and Codex CLIs) that feed the build hash.
- `conversation-state.ts` - Host-side access to the agent-writable conversation-state directory (`claude-state`, `codex-state`, `goose-state` under the bundle directory, mounted at `~/.claude/`, `~/.codex/`, `~/.local/share/goose/sessions/`). Bounded, no-follow transcript probes (`hasStoredTranscript`, `findStoredConversation`, `hasCodexRollout`, `findLatestCodexThread`), host-only conversation records under `<bundleDir>/agent-conversations/`, `buildPtyConversationEnv`, and `syncConversationStateClaudeMd`, which writes the seeded CLAUDE.md without following links (a directory planted at that name fails session start) or unlinks it.
- `container-workspace.ts` - `buildContainerWorkspaceMount(dir, { readonly })`: the `/workspace` mount, read-only for a read-only workspace (dependency layers too).
- `workflow-dependency-cache.ts` - Workflow runtime dependencies: a host-provisioned shared base per content key under `<home>/workflow-dependency-bases/`, built in a short-lived provisioning container (`runWorkflowDependencyProvisioner` in `docker-infrastructure.ts`) and never mounted into an agent container, verified by a host-side `<base>.provisioned.json` record, plus a writable copy per run under `workflow-runs/<id>/deps/`. `provision-lock.ts` is built on `../docker-workload/process-lock.ts`. Host manifest verification streams directories and stops above 100,000 entries, depth 64, 16 GiB content or 64 MiB metadata; hashing rejects files that grow beyond their walked size. Provisioning disk/inode quotas remain separate.
- `types.ts` - Type definitions for container lifecycle (`ContainerRuntime`, `DockerContainerConfig`, `DockerMount`, etc.).
- `platform.ts` - Platform detection for the **Docker** transport split. macOS Docker uses TCP (VirtioFS doesn't support UDS); Linux Docker uses UDS. Not consulted for apple-container.
- `orientation.ts` - Generates MCP client configuration and system prompt files for the agent container. Written to a read-only bind-mounted orientation directory. Its server listing includes the virtual `workflow` server when the bundle has a commit channel, and `OrientationContext.workspaceReadOnly` switches the workspace wording.
- `audit-log-tailer.ts` - Tails the JSONL audit log via `fs.watchFile()` and emits `DiagnosticEvent` callbacks for outcome records only (never the write-ahead `dispatching` records). It starts where the session says (`startOffset`, `'end'` for logs shared with earlier sessions), reads line-exact in chunks (lines over 64 MiB are skipped), and `stop()` removes only its own listener.

## MITM proxy & credentials

- `upstream-response.ts` - Every HTTP relay response callback uses `guardUpstreamResponse`: upstream statuses must be integers from 100 through 599, and a callback/header failure answers 502 with connection close, or destroys an already-started response. Keep validation inside the asynchronous callback; the request listener's synchronous guard cannot contain a later response failure. Raw WebSocket handshake responses enforce the same status contract before writing.
- `mitm-proxy.ts` - TLS-terminating MITM proxy (the file header lists every duty). Outer HTTP server on UDS handles CONNECT: the authority is parsed strictly (`proxy-authority.ts`) and routed to a provider, a package registry or a passthrough target. Inner HTTP server processes decrypted requests: endpoint filtering, the credential gate (`provider-credentials.ts`), request sanitizers, the budget gate, upstream forwarding with SSE streaming (no hop-by-hop or `Set-Cookie` response headers relayed), and refusal of WebSocket upgrades on provider hosts. Leaf certificates are issued only for the CONNECT host (a ClientHello naming another SNI is refused) from one shared leaf key pair per CA generation (`prepareLeafIssuance`, awaited in `start()`), cached in a process-wide LRU of 256 contexts (`ca.ts`). Per-bundle resource ceilings and deadlines live in `mitm-resource-limits.ts` (`MitmProxyOptions.resourceLimits` for tests); each proxy creates one registry metadata budget and one npm publish-time cache. The control API (dynamic hosts) needs the per-bundle bearer token (`config.mitmControlToken`, `MITM_CONTROL_TOKEN` in relays).
- `budget-gate.ts` - Host-enforced token and cost budget per bundle (`maxTotalTokens`, `maxEstimatedCostUsd`, cumulative for the bundle). Batch and workflow bundles (`turn` mode) forward completions only while the host runs an agent turn (`DockerAgentSession` opens one per exec); PTY bundles (`session` mode) get one session-long allowance. Each request's output cap is pre-charged; settlement charges measured usage at list prices (or the gateway's reported cost) and a conservative estimate when usage cannot be measured. Refusals are local 400s marked `x-ironcurtain-refusal` (`ironcurtain_budget_exhausted`, `ironcurtain_no_active_turn`); the first budget refusal latches the gate and stops the running turn.
- `provider-credentials.ts` / `credential-carriers.ts` - The credential gate: every credential carrier (credential headers, cookies, credential query parameters) is stripped, the session sentinel is swapped for the real key in the provider's configured location only, and any other credential gets a local 401. Keyless requests reach only a provider's declared `unauthenticatedEndpoints`.
- `request-sanitizers/` - Allowlist sanitizers per wire protocol (`anthropic.ts`, `openai.ts`, `gemini.ts`; shared primitives in `core.ts`), the OpenRouter gateway sanitizer chained in front (`openrouter.ts`, `chainSanitizers`, `GatewayDefinition.gatewaySanitizer`), and `content-encoding.ts` (compressed request bodies are decoded before sanitizing; unknown codings get 415). Providers bind them with `ProviderConfig.sanitizedEndpoints`; the proxy forwards the canonical JSON and answers 400/415 instead of forwarding a body it cannot parse or sanitize. They remove provider-hosted tools and connectors (web search and fetch, remote MCP servers, code execution, URL-sourced content).
- `llm-observation/` / `sse-extractor.ts` - The `ResponseObservationHub` decodes and frames each response once for its passive consumers; the token stream (web UI, `observe`, workflow token counter, OpenRouter cost) is one of them (`TokenStreamSseParser`, `createTokenStreamConsumer`, `createBoundedJsonResponseCapture`). Forwarding is always a plain pipe.
- `outbound-transport.ts` - Destination-bound provider/registry transport. It owns Host/SNI, applies direct SSRF and DNS-rebinding checks (through `../net/address-policy.ts`), keeps keep-alive pools per policy (optional `close()`), or routes to one fixed parent proxy without exposing a generic CONNECT operation to callers. The fixed-parent transport (`createParentProxyOutboundTransport`) is tested but not yet wired: no production path selects it. It is reserved for the IronCurtain-in-IronCurtain slice (`docs/designs/ironcurtain-in-ironcurtain-hermetic-slice.md`, Implementation status) and is never a user-configurable parent-proxy setting.
- `selected-agent-artifact.ts` / `oci-image-archive.ts` / `oci-image-archive-canonicalizer.ts` - Apple same-VM selected-current-agent transport. One inspected Apple image resolution is exported to a canonical Docker-loadable archive, cached as an observational optimization, hard-linked into the admitted lease, verified immediately before inner load, and compared with both the stopped outer VM and loaded inner image before agent release. Source-runtime names are advisory; graph digests, platform, labels, and the canonical output name define the transport. Docker Desktop pins the outer agent directly by immutable image ID and does not save, stage, or load this archive. Archive checks protect host tooling and transport correctness; the bundle image remains untrusted. Feature-off sessions stage no artifact and receive no private daemon or nested-Docker orientation.
- `../docker-workload/client-toolchain.ts` - Exact client/daemon/plugin compatibility preflight. Its observations are provenance and operational compatibility, not bundle-code attestation or image-derived host-security authority.
- `linux-dependency-abi.ts` - Strict Linux Node/npm/libc/native-module ABI manifest and disposable `isolated-vm`/`node-pty` load probe for ABI-keyed dependency volumes. A matching manifest is necessary but never substitutes for executing the probe inside the target runtime. Not yet wired: no production caller. Reserved foundation for the IronCurtain-in-IronCurtain harness's Linux-built dependency artifact and later native Linux work.
- `scripts/qualify-backend.ts` - Backend release gate for the current checkout. It runs the local Vitest entrypoint over the source-controlled backend suite and owns reporter/output flags; failed execution, missing suites, and skipped/todo/pending results fail the gate. Reports are always retained, with `--report-dir` selecting their location. WSL qualification prepares all three agent images before its no-skip suite and runs bounded production smoke gates. Admission checks validated environment facts, complete profiles and watchdog policy values, fixed relay endpoints, and effective container configuration. Qualification reports and observed image/tool versions do not grant host authority.
- `resource-watchdog.ts` plus `../docker-workload/{bundle-lease,bundle-revocation,process-lock,resource-watchdog-supervisor}.ts` - Host-side observed-state enforcement shared by Docker and Apple. Admission and lease mutations share an atomically published, process-start/token-bound lock; the owner-only lease records requested runtime names before create and exact runtime IDs afterward. New leases are schema v3 and record the coordinator's process-start identity; v1 and v2 leases stay readable and are never upgraded. New leases and supervisor status carry the complete bounded watchdog policy (policy v2: per-runtime storage coverage from `observed-storage.ts`, Apple rootfs-image blocks above the activation baseline and the Desktop VM disk plus the daemon volume, with a `runtime-reserve` trip; admission refuses a runtime without coverage). Liveness is judged on each observer's own monotonic clock (`peer-liveness.ts`). The detached supervisor (entrypoint resolved beside the running module, so `tsx src/cli.ts` works unbuilt; fatal errors go to `supervisor-stderr.log` in the lease directory) attests before daemon release, survives coordinator exit, remeasures normal-stop proof, and on a trip revokes exact generation-owned resources without durable writes, frees the per-lease emergency reserve (`emergency-reserve.ts`), takes two label-filtered empty inventories, closes the lease, and exits. Incident details are bounded. The lease's `paths.exchangeRoot` is reserved for the IronCurtain-in-IronCurtain slice. Nothing mounts it, but it must stay required in every lease schema version: `paths` is strict, and reconciliation parses every lease directory and blocks admission on one it cannot read.
- `../docker-workload/scanner-fixture.ts` and `test/docker-workload/fixtures/vulnerability-fixture/` - Strict adjudicator plus static deterministic target/scanner images and internal-only Compose workflow. Vulnerable/patched verdicts, bounded unready/egress failures, exact image IDs, foreign-object preservation, and cleanup have a gated live Docker Desktop test.
- `package-egress-proxy.ts` / `package-egress-address-policy.ts` / `package-egress-ledger.ts` / `docker-build-shim.ts` / `docker/build-trust-runtime/` - Dedicated package-registry MITM and hardened BuildKit trust injection for admitted nested-Docker `packages` mode. It accepts only frozen package routes, screens every selected destination, injects public trust through the qualified runc envelope, and has no generic CONNECT authority. The retired current-Dockerfile hash/path build-egress listener must not be restored.
- `../docker-workload/desktop-relay.ts` and `docker/nested-relay/` - Shared fixed-target relay lifecycle. It renders and re-inspects a non-root, read-only, resource-bounded container on an isolated dual-stack network. macOS Desktop uses the fixed TCP upstream; WSL binds exactly one host policy socket read-only, with no host aliases or published ports. Neither mode grants a caller-selected protocol or arbitrary destination.
- `ca.ts` - `loadOrCreateCA()` uses a parent lifecycle lock to verify or atomically replace the 2048-bit RSA CA under `~/.ironcurtain/ca/`. Partial, linked, mismatched, malformed, expired, legacy, or potentially exposed state receives a fresh key; unsafe parent storage first enters a durable owner-only replacement-pending mode, then the CA is displaced and the parent finalized at `0700`. `runtime-trust.ts` stages exactly the normalized public certificate and public-root bundle into the read-only orientation mount. Existing bundles keep their in-memory CA, images are CA-neutral, and the key never enters containers.
- `provider-config.ts` - `ProviderConfig` interface and built-in providers (Anthropic, OpenAI, Google). `isEndpointAllowed()` does strict path matching with glob support (`*` matches one or more RFC 3986 unreserved characters within one segment, never only dots). Query strings are stripped before matching. `sanitizedEndpoints` binds request sanitizers (`resolveRequestSanitizer`), `unauthenticatedEndpoints` lists the only keyless routes, and `maxRequestBodyBytes` caps buffered request bodies (32 MiB default, 50 MiB for OpenAI and Codex). The `RequestBodyRewriter` context carries an optional `cacheKey` (the stable conversation id) used for OpenRouter `session_id` injection. Its `agentKind` distinguishes one-shot `batch`/`workflow` requests from interactive `pty` requests: `anthropicRequestRewriter` strips Claude Code's schedule-skill tools only from one-shot requests, and they remain available in PTY sessions.
- `../config/provider-definitions.ts` / `../config/gateway-client.ts` - Built-in gateway metadata and credential-free harness bindings. Model selection is client-owned for direct gateways and proxy-owned for OpenRouter. Never send a selected proxy model back through the model map; aliases/configuration retain fresh request IDs.
- `gateway-runtime.ts` - Shared built-in gateway `ProviderConfig` factory and request rewriting. Copies routing facts per session, consumes independently declared endpoint authorization, and preserves host-only credentials. Native OAuth tokens remain refreshed outside this snapshot. `openrouter.ts` and `zai.ts` retain compatibility factories that delegate here; OpenRouter request preferences are localized in `../config/openrouter.ts`.

- `fake-keys.ts` - `generateFakeKey(prefix)` creates sentinel keys with `crypto.randomBytes(24)` (192 bits).
- `oauth-credentials.ts` - OAuth credential detection and macOS Keychain extraction. `detectAuthMethod()` determines whether to use OAuth or API key auth for Docker sessions. Credentials carry a `clientKind` (`'anthropic-cli'` for the CLI store at `~/.config/anthropic/credentials/default.json`, undefined = Claude Code); `refreshOAuthToken()` picks the OAuth client ID, token endpoint, and grant encoding from it — a refresh grant presented with the wrong client is rejected as `400 invalid_grant`. Credential files are written with `writePrivateFileAtomicSync` (`../util/atomic-write.ts`); a refresh write-back passes `{ refreshedFrom }` and keeps a token the host stored in the meantime, and callers use the credentials the save returns.
- `oauth-token-manager.ts` - Proactive/reactive OAuth token refresh (also used for Codex's ChatGPT OAuth). Coordinates with the host Claude Code process: before refreshing it re-reads the credentials file and, for Keychain-sourced credentials (macOS), the Keychain, and adopts a token the host already refreshed. When it refreshes itself (it holds a refresh token), it writes the result back to the file or to the Keychain. Shares a single in-flight refresh promise across concurrent callers.

## Token-trajectory capture (opt-in, training data)

Verbatim, byte-faithful capture of the agent↔provider HTTP exchanges, written as per-session JSONL for SFT/RL training data. Off by default; enabled with `--capture-traces` (`start`, `workflow start`, `daemon`) or `capture.enabled` in config. Zero cost when disabled (no taps installed, no allocations). See the root [`TRAJECTORIES.md`](../../TRAJECTORIES.md) for usage and [`docs/designs/mitm-token-trajectory-capture.md`](../../docs/designs/mitm-token-trajectory-capture.md) for the design.

- `trajectory-types.ts` - `ExchangeRecord` schema, manifest entry types, `PoisonReason`, `CaptureConfig`, and the `redactHeaders` helper (strips every credential carrier from `credential-carriers.ts` — `authorization`, `x-api-key`, `x-goog-api-key`, `api-key`, `anthropic-api-key`, `cookie`, `cookie2` — plus `set-cookie` and `proxy-authorization`, defensively).
- `trajectory-capture.ts` - `TrajectoryCaptureWriter` dispatcher: per-session file handles + a single append-only `manifest.jsonl`, single-flight `setImmediate` drain loop, watermark-defended unbounded queues, two-phase `endSession`, and the **exchange-scoped drop model** (a truncated/aborted exchange, or one that exceeds a capture limit, is dropped whole and counted in `session-end.abortedExchanges`, leaving the rest of the session valid; session-wide `poisoned`/`poisonReason` is reserved for writer/parser-level hazards — `disk-error`, `queue-overflow`, `reassembly-failure`, `unsupported-encoding`, `infrastructure-teardown` — and is announced by a `session-poisoned` manifest entry at poison time; never a partial record). Counters are bumped post-`appendFile` so manifest `exchanges` matches on-disk line count.
- `trajectory-limits.ts` - Capture resource limits (decoder, SSE framer and verbatim body caps). Exceeding one costs only that exchange, never the session. The request tee of a streamed exchange is capped at the provider's request limit; past it the request is still forwarded but the exchange is dropped.
- `trajectory-reassembler.ts` - SSE → final-message reassembly with strict byte fidelity (no `JSON.parse`→`stringify` round-trip; `thinking` signatures, block order, and `redacted_thinking` preserved; depth-aware field lookup). `SseLineSplitter` decodes through a `StringDecoder` so multibyte UTF-8 split across chunks isn't corrupted. Anthropic implemented; OpenAI stubbed for v0. `providerForHost(host, path?)` is the host→provider classifier and `createReassembler(host, path?)` picks the reassembler; both are **path-aware** for `openrouter.ai` (one host, three wire formats): `/api/v1/messages` → Anthropic, `/api/v1/responses` → Responses reassembler, `/api/v1/chat/completions` → raw-bytes-only (no reassembler, v0). The token-stream tap's own classifier `resolveSseProvider(host, path?)` in `mitm-proxy.ts` is path-aware the same way — the two seams are independent — and `isLlmMessagesEndpoint` matches the three `/api/v1/*` OpenRouter paths.
- `trajectory-tap.ts` - Per-exchange capture tap: request-body tee, response-body fan-out, and `createResponseCaptureInlet` (decompresses per `content-encoding` — gzip/deflate/br — before the reassembler; unsupported encodings like zstd poison the session, while a decoder resource limit drops only the exchange).
- `mitm-proxy.ts` (capture role) - The inner request handler snapshots `captureSessionId`/`capturePersona` (decoupled from `tokenSessionId`), gates on `isCapturableEndpoint` (completion endpoints only — see `provider-config.ts` `captureEndpoints`), and **fans out** the upstream response into a forwarding branch (raw bytes → agent, unchanged) and a capture branch (decompress → tap). The capture branch never applies backpressure to forwarding. Credential boundary: captures the agent-facing side only (sentinel keys), verified by `test/docker/trajectory-credential-leakage.unit.test.ts`. Capture records the request body before sanitization (the agent's intent).

Lifecycle is driven through `DockerInfrastructure.beginCaptureSession()` / `endCaptureSession()`; standalone sessions drive it in owns-infra mode, workflows from the orchestrator with `persona`/`fsmState`. The internal `MitmProxy.setCaptureSessionId` / `setCapturePersona` setters are wrapped by those bundle methods — orchestrators never call them directly.

## Proxy tools & package registry

- `proxy-tools.ts` - Hardcoded MCP tool definitions, annotations, and policy rules for domain management. Injected into the ToolCallCoordinator during construction for policy evaluation and audit logging. `validateProxyToolArguments` runs in the security pipeline before policy evaluation.
- `code-mode-proxy.ts` - MCP server exposing a single `execute_code` tool backed by the UTCP Code Mode sandbox. Docker agents send TypeScript via this tool, sharing the same V8 execution engine as builtin Code Mode sessions. Implements the `DockerProxy` interface. Both Unix and TCP listeners cap unread Code Mode input at 1 MiB; the shared socket transport frames with fixed pages and a scan cursor. Every accepted agent connection gets its own MCP `Server` over the one shared Sandbox/ToolCallCoordinator (separate JSON-RPC id spaces, never evicted; the coordinator's call mutex serializes tool calls) and its own circuit-breaker lane, so several agent processes per container (fan-out lanes, nested CLIs) work at the transport level. It runs up to 4 scripts at once (`CODE_MODE_PROXY_MAX_CONCURRENT_CHAINS`), cancels a script (and withdraws its escalations) when its MCP request is cancelled or its connection closes, bounds the reply (`[logs]` and the result share the 100 KB result-size budget), and logs agent-triggered warnings through the rate-limited `agent-warning-log.ts`. `DockerProxy.getPolicySwapTarget()` returns a narrow `PolicySwapTarget` handle (only `startControlServer`) that the workflow orchestrator uses to attach a control server to the live coordinator; single-session callers never use it. `DockerProxy.getEgressAuthorizer()` hands the MITM the coordinator's egress decision under policy-evaluated egress.
- `registry-proxy.ts` - URL parsing, metadata filtering, and tarball backstop for npm, PyPI, Debian, and cargo (crates.io) package registries. Built-in registry configs for each. The proxy is read-only (bodiless GET/HEAD on a per-host route allowlist, `classifyRegistryRoute`; client credentials and non-allowlisted headers are stripped by `registry-request-gate.ts`), requires canonical request paths (`registry-request-path.ts`), gates PyPI per distribution file, and records every forward and refusal in `package-audit.jsonl`. Metadata is read streaming and bounded: `json-stream-scanner.ts`, `registry-metadata.ts`, `registry-metadata-budget.ts`. `package-client-env.ts` sets `NPM_CONFIG_AUDIT=false` and `NPM_CONFIG_FUND=false` in containers.
- `package-types.ts` - Shared types for the package installation proxy (`RegistryConfig`, `PackageIdentity`, `PackageValidator`, etc.).
- `package-validator.ts` - Package validation against allowlist/denylist/age-gate rules. First-match semantics: denylist > allowlist > age gate > default allow.

## Proxy passthrough (domain management)

The `proxy` virtual MCP server (`proxy-tools.ts`) exposes `add_proxy_domain`, `remove_proxy_domain`, and `list_proxy_domains`. These are hardcoded tool definitions (not LLM-generated) with hardcoded policy rules: `add` → escalate (human-only: never the auto-approver, a whitelist pattern or "approve all"), `remove` → allow, `list` → allow. Injected into the ToolCallCoordinator during construction alongside compiled rules.

**Domain validation** (`validateDomain()` in `proxy-tools.ts`, run by `validateProxyToolArguments` before policy evaluation): Rejects IP addresses in every spelling, `localhost`, `*.docker.internal`, local and metadata names (`*.localhost`, `*.local`, `*.internal`, `*.home.arpa`, `metadata.google.internal`, ...), names >253 chars, and invalid format.

**Connection modes in `mitm-proxy.ts`:**

- **Provider/registry CONNECT** → TLS-terminating MITM (credential swap, endpoint filtering, request sanitizing, budget gate). Used for LLM API providers and package registries.
- **Passthrough CONNECT** → Approvals are `host:port`: 443 by default, 80 on request (`add_proxy_domain` accepts `host`, `host:443` or `host:80`); any other port is refused. A 443 tunnel is a raw TCP tunnel relayed only after the client's TLS ClientHello names the approved host in its SNI (`tls-client-hello.ts`; bounded read). Port 80 is served by an HTTP-aware tunnel that pins the Host header, including `ws://` upgrades. No credential swap or content inspection. Used for dynamically added domains. (Behind the reserved fixed-parent transport, which no production path selects yet, a 443 passthrough would be TLS-terminated with the SNI checked instead of tunneled.)

**Plain HTTP WebSocket upgrade** (`outerServer.on('upgrade')`) handles `ws://` connections via `HTTP_PROXY`. The `bridgeWebSocketUpgrade()` helper forwards the upgrade to the upstream and pipes both sockets bidirectionally. The inner (TLS-terminated) server refuses WebSocket upgrades on provider hosts on purpose.

**Policy-evaluated egress** (opt-in `egressPolicy.enabled`, `MitmProxyOptions.policyEvaluatedEgress`): every destination that is not a provider or registry becomes an audited `network/request` decision of the session's policy engine (`setEgressAuthorizer`, see `../trusted-process/egress-policy.ts`), at host:port for CONNECT and per path for plain HTTP, with a per-target decision queue. Escalate-once: human approvals land in the passthrough set and human denials are remembered. `IRONCURTAIN_MITM_ALLOW_ALL_HOSTS` is deprecated and ignored under this opt-in.

**Lifecycle:** Approvals are session-scoped (in-memory `passthroughHosts`, keyed `host:port`; `list_proxy_domains` reports `host:port`). `removeHost` tears down the tunnels opened under the approval (raw tunnels, WebSocket bridges, port-80 tunnels, and the TLS-terminated passthroughs of the reserved fixed-parent transport). Tunnels have an idle timeout and a cap, and every tunnel is destroyed on `stop()`.

## Agent adapters

- `agent-adapter.ts` - `AgentAdapter` interface. `getProviders(authKind?)` returns required LLM providers (OAuth or API key). `buildEnv(config, fakeKeys)` builds common container env vars with fake keys instead of real ones; optional `buildBatchEnv(config, fakeKeys)` adds one-shot-only overrides and is never applied to interactive PTY sessions. `AgentResponse.agentThreadId` reports a CLI-minted conversation id, passed back as `buildCommand`'s `agentThreadId`.
- `agent-registry.ts` - Simple `Map`-based registry of agent adapters. `registerBuiltinAdapters()` lazily loads the Claude Code, Goose and Codex adapters and takes no config; adapters read model and provider per session.
- `adapters/claude-code.ts` - Claude Code adapter. Auth-aware `buildEnv()` sets `CLAUDE_CODE_OAUTH_TOKEN` or API key. `getProviders()` returns OAuth or API key providers based on `authKind`.
- `agent-response-output.ts` - Combined batch stdout/stderr parsing cap of 4 MiB; overflow throws a distinct error rather than parsing truncated JSON or causing an empty-output retry. `DockerAgentSession` checks every adapter; Goose also checks direct extraction calls and uses the shared linear terminal-sequence scanner.
- `adapters/goose.ts` - Goose adapter. Generates Goose YAML config for MCP extension discovery, orientation scripts for PTY mode, and provider-specific env vars (Anthropic, OpenAI, Google). Uses named sessions stored in the `goose-state` mount (`~/.local/share/goose/sessions/`).
- `adapters/codex.ts` - Codex CLI adapter (ChatGPT OAuth). Generates `codex-config.toml` with one provider binding per route and `supports_websockets = false`; `CODEX_CLIENT_VERSION` must match `docker/Dockerfile.codex`. Resumes the recorded thread (`codex exec resume <thread>`, PTY `codex resume <thread>`), never `--last`.
- `adapters/shared-scripts.ts` - Shared shell script generators (e.g., `resize-pty.sh`) and prompt sections used by the adapters.
- `claude-md-seed.ts` - Builds `CLAUDE.md` content seeded into the container's `~/.claude/` for Claude Code sessions (written by `conversation-state.ts`). Contains memory behavioral rules (pre-response MCP tool call protocol). On a borrowed workflow bundle memory is always off, so the file is only ever removed there.

**Quota exhaustion contract:** adapters MUST populate `AgentResponse.quotaExhausted` when the underlying CLI surfaces a 429-class envelope; the workflow orchestrator short-circuits on this signal instead of retrying. See `adapters/claude-code.ts` for the canonical implementation. Codex classifies only structured failure events and stderr and needs an explicit HTTP 429, status or provider quota code; a run that wrote nothing to stdout is a `hardFailure`.

## Dual session modes: keep in sync

`docker-agent-session.ts` (batch mode) and `pty-session.ts` (PTY mode) have parallel initialization paths that share adapter infrastructure but assemble container configs independently. When adding a mount, env var, or container lifecycle feature to one mode, always check the other mode and apply the same change if applicable. Past bug: conversation state mount was added to PTY mode but missed in batch mode, so batch conversations could not resume across container recreations.

## PTY mode

- `pty-session.ts` - PTY session orchestration. Docker sessions use the Node.js PTY proxy and socat transport; Apple Container sessions attach through runtime-native `container exec -it`. Handles terminal lifecycle, BEL on escalation, and registration file lifecycle. Ctrl-C (or SIGTERM/SIGHUP) during setup tears down what was created.
- `pty-host-terminal.ts` - Host-terminal side of an interactive container PTY, shared by the socat relay (`attachPty` in `pty-session.ts`) and Apple's runtime-native exec (`relayHostPty`): every agent output chunk passes through `../terminal/terminal-output-filter.ts`, and terminal modes are restored when the relay ends.
- `pty-resize-queue.ts` - Serialized container PTY resizing: at most one resize exec in flight, always applying the latest size.
- `pty-types.ts` - Type definitions for PTY sessions (`PtySessionRegistration`, socket/port constants).

**PTY transport:** On Linux Docker, the container-side socat listens on a UDS in the bind-mounted `sockets/` directory. On Apple Container, the outer process remains `sleep infinity` on `--network none` and the agent starts through `container exec -it`; no host PTY relay is published. On macOS Docker Desktop it uses TCP through the socat sidecar. Only the `sockets/` subdirectory (or its individual proxy socket files on apple-container) is mounted into the container -- not the full session directory -- so the container cannot access escalation files, audit logs, or other session data.

## Security model

Real credentials (API keys or OAuth tokens) never enter the container. The agent receives a fake sentinel key; the MITM proxy validates it and swaps for the real credential on the host side. Every other credential carrier is stripped, any credential other than the sentinel gets a local 401, and keyless requests reach only declared `unauthenticatedEndpoints` (`provider-credentials.ts`). OAuth is auto-detected from `~/.claude/.credentials.json` and preferred over API keys; override with `IRONCURTAIN_DOCKER_AUTH=apikey`. Endpoint filtering ensures only specific API paths are accessible (e.g., `POST /v1/messages`), and request sanitizers remove provider-hosted tools from completion requests.

Package installations are mediated by the registry proxy, which is read-only, allowlists routes per registry host, audits every forward and refusal, and validates packages against allowlist/denylist rules and an age gate (quarantine period for new versions) before allowing downloads from npm, PyPI, Debian, or crates.io repositories.
